# 提交信息生成器

## 核心约束（必读）

1. **不展示 git 原始信息**：生成结果中不要输出 STAGED_FILES、DIFF 等内容，只输出最终的提交信息。
2. **实时获取数据**：每次执行必须实时调用 git 命令，不要使用缓存或假设。

## 工作流程

### 第 1 步：收集信息

执行以下 git 命令获取当前状态：

```bash
git diff --cached --name-only
git diff --cached --stat
git branch --show-current
git log --oneline -10
```

### 第 2 步：分析变更内容

根据 `git diff --cached --name-only` 的文件名和 `git diff --cached --stat` 的统计信息，推断变更类型和范围。

读取 `git log --oneline -10` 的输出，分析最近 5-10 条提交的风格，包括：

- emoji 前缀风格（中文 vs 英文）
- 标题格式和长度
- 主体内容格式

**风格一致性很重要**：项目的提交历史形成了团队约定的风格，遵守它能让提交记录保持可读性和专业性。如果历史中没有统一风格，按下方默认规范执行。

### 第 3 步：生成提交信息

根据 diff 内容选择 emoji，按模板生成。

## 提交信息模板

```
[emoji] [中文标题，不超过 50 字]
- 具体变更 1
- 具体变更 2
- 具体变更 3
```

规则：
- 标题必须有 emoji 前缀
- 标题使用中文，简短清晰（不超过 50 字）
- 使用中文标点
- 主体用 `- ` 列表，每个条目描述一个具体变更

## 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 暂存区为空 | 输出提示："暂存区没有待提交的文件，请先 git add" |
| 涉及多种变更类型 | 选择影响最大/文件最多的类型作为主 emoji |
| 新仓库无历史提交 | 直接按上方默认规范（中文 emoji + 中文标题）生成 |
| 变更内容极小（如修改标点） | 标题简洁即可，不需要主体列表 |

## 示例

**示例 1：修复 Bug**
```
Input: git diff --cached 显示修复了 sidebar.tsx 中的溢出 bug，并更新了相关 CSS
Output: 🐛 修复侧边栏内容溢出问题
- 修复 sidebar.tsx 中列表项溢出容器的问题
- 更新 sidebar.css 添加 max-height 和 overflow 控制
```

**示例 2：新增功能**
```
Input: 新增了 login.tsx 和 auth.ts 两个文件
Output: ✨ 新增用户登录功能
- 新增 Login 登录页面组件
- 新增 auth 工具模块，封装登录请求逻辑
```

**示例 3：文档 + 配置混合（选主要变更）**
```
Input: 修改了 vite.config.ts 并更新了 README.md 中的安装说明
Output: 🔧 优化 Vite 构建配置并更新文档
- 优化 vite.config.ts 中的路径别名配置
- 更新 README 安装说明以匹配新配置
```
